**INP:** not reported. No field data exists for this build (it is not deployed). TBT above is a lab proxy only.

**Improvements:** mobile Performance rose on every tested page (72 → 90 home; 82 → 92 vehicle detail; 81 → 93 gallery); desktop is 98–100. Mobile TBT fell 67–93% on five of six pages (home 561 → 40 ms); page weight fell up to 68% (vehicle detail 1,371 → 437 KB); FCP and LCP improved on every page in both form factors; CLS ≤ 0.005 everywhere. A 4×-CPU trace of the homepage shows layout work down from 819 to 283 ms and long tasks from 14 to 2.

**Regressions / unmet targets (lab):**

- Mobile **Speed Index** worsened on Home (3.58 → 5.07 s), Gallery (3.83 → 4.83 s) and North Goa (2.87 → 4.89 s). Investigation: in Lighthouse's own observed trace, first paint on these pages is gated by the first-visit intro splash overlay and is bimodal (~0.9 s or ~2.3 s) in **both** builds; the final build simply lands in the slow mode consistently. Outside Lighthouse, a cold, uncached Chromium load paints earlier than the baseline (home FCP ~330 ms vs ~390–650 ms; six runs each). The client chose on 2 November 2026 to keep the splash; this lab regression is accepted.
- Mobile **LCP** remains above 2.5 s on five of six pages in the simulated profile (2.61–3.08 s; only Contact, 2.04 s, meets it). Real Chromium with 4× CPU and a throttled network measured the homepage LCP (the H1) at ~1.1–1.6 s; only post-launch field data can confirm the 75th-percentile value.
- Contact mobile TBT 25 → 72 ms and gallery desktop TBT 0 → 15 ms (both far below the 200 ms threshold); client JS grew 0.4 KB (Brotli) for the ribbon control, poster loader and menu focus handling.
- The images remain the largest payload on the gallery (939 KB mobile) because it intentionally shows many photographs; they are lazy, correctly sized and compressed.

Accessibility issues found and fixed in Stage 2:

1. Header phone link, card "View details" links: accessible names did not contain the visible text (WCAG 2.5.3). Names now start with the visible label.
2. Mobile menu: the drawer precedes its toggle in DOM order, so Tab skipped the open drawer. Focus now moves into it on open and cycles drawer ↔ toggle; Escape closes and restores focus. The drawer becomes visible immediately on open so it can take focus (slide animation unchanged).
3. Auto-scrolling ribbon lacked a pause mechanism (WCAG 2.2.2) — pause button added.
4. Floating WhatsApp button sat outside any landmark; quick-contact bar used `aria-label` on a plain `div`; labelled ribbon and scroll regions lacked roles — now `aside`/`nav`/`group`/`region`.
5. Gallery images repeated the caption already in the button name (`alt=""` now, button name unchanged).
6. Breadcrumb links were under the 24 px target size; padding added with offsetting negative margin (no visual shift).

Manual checks not possible here: screen readers (NVDA/VoiceOver/TalkBack), physical iOS/Android devices, Safari/Firefox engines (tests ran in Chromium). Automated testing does not prove full WCAG conformance.
